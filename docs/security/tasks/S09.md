# S09 — Stripe, kupon i dostęp do pakietu

Cel: prawidłowe bezpłatne dwa miesiące z kuponu oraz bezpieczne przejście na opłaty. Zależność: S08. Następne: S10.

## Zakres

- Najpierw odczytaj rzeczywisty kupon/promotion code, procent/kwotę, czas trwania, produkty/ceny, waluty, ograniczenia użyć i sposób stosowania. Zapisz identyfikatory i parametry, bez danych klientów i kluczy.
- Użytkownik potwierdził kupon; nie dodawaj triala ani drugiej promocji. Zerowa faktura może oznaczać aktywną subskrypcję, nie `trialing`. Zbadaj różnicę miesięcy kalendarzowych i liczby okresów rozliczeniowych.
- Zweryfikuj zbieranie metody płatności również przy zerowej pierwszej fakturze. Sam `mode: subscription` nie jest wystarczającym dowodem. Ustal pierwszy termin i cenę opłaty z faktycznej subskrypcji/rabatu.
- Nadawaj uprawnienia z wiarygodnego stanu Stripe, nie z parametru success URL ani samego metadata. Sprawdź subscription status, powiązanie użytkownik/customer, ceny i dozwolony pakiet. Nie wymagaj dodatniej płatności dla poprawnego rabatu 100%.
- Obsłuż podpis webhooku, duplikaty, dostarczenie w innej kolejności, opóźnioną płatność, brak płatności, anulowanie, zmianę pakietu i uzgodnienie stanu po pominiętym zdarzeniu. Checkout powinien być odporny na podwójne kliknięcie i równoległe utworzenie dwóch subskrypcji.
- Checkout, potwierdzenie i ustawienia pokazują promocję, kolejną opłatę i sposób rezygnacji; nie obiecuj innego terminu niż Stripe. Dostęp FREE pozostaje oddzielny.

## Pliki i skille

Skill lyamo-stripe obowiązkowo; lyamo-supabase dla migracji. `features/billing/services/`, `api/billing/`, `api/webhooks/stripe/`, plan limits, UI cennika/ustawień i testy idempotencji.

## Kryteria odbioru

- Stripe Sandbox/test i Test Clock, jeśli wspierany dla przebiegu: pierwszy okres 0, drugi zgodnie z kuponem, pierwsza płatna faktura, anulowanie przed opłatą i nieudana płatność.
- Ważny pakiet przy rabacie 100%, brak pakietu dla niekwalifikującego statusu; powtórne/stare webhooki nie nadpisują nowszego stanu.
- Podwójne żądanie checkout nie tworzy niekontrolowanie dwóch subskrypcji.
- Brak rzeczywistych obciążeń i zmian istniejących subskrypcji klientów podczas testu.

Raport reports/S09.md: potwierdzony model promocji, daty/kwoty z testu, wymagane ustawienia Stripe i ryzyka wydania. Jeśli brak połączenia, nie oznaczaj testów kuponu jako wykonanych.
