# S03 — cykl dostępu web i mobile

Cel: jednoznacznie wydawać, odnawiać i odwoływać dostęp do konta. Zależność: S02. Następne: S04.

## Zakres

- Reset hasła odwołuje wszystkie wcześniejsze sesje i refresh tokeny; zmiana hasła odwołuje inne urządzenia i odnawia bieżące. Wylogowanie odwołuje sesję danego urządzenia.
- Zapewnij skuteczne odwołanie także wydanego access JWT (np. kontrola wersji/sesji przy autoryzacji). Nie wystarczy usunąć refresh token i pozostawić 15 minut aktywnego dostępu.
- Rotuj refresh tokeny atomowo, wykrywaj ponowne użycie i odwołuj rodzinę sesji; uwzględnij równoczesne prawidłowe odświeżenia oraz utratę odpowiedzi sieciowej bez przypadkowego osłabienia ochrony.
- Ujednolić walidację JWT (jawne algorytmy, issuer, audience), weryfikację wymaganych stanów użytkownika, czas bezczynności i czas absolutny. Zdefiniuj migrację starych sesji.
- Dodaj listę sesji/urządzeń i wylogowanie jednej/wszystkich; nie sugeruj pewnej identyfikacji urządzenia z samego User-Agent.
- Dodaj mechanizm świeżego uwierzytelnienia dla usunięcia konta i dołączania metod; obsłuż konto bez hasła przez właściwego dostawcę. Zintegruj z S02. S07 rozszerzy go o MFA.
- Zapisuj minimalne zdarzenia bezpieczeństwa i powiadomienia o istotnych zmianach; kanał wysyłki/retry rozwinie S04. Ustal rozsądną retencję bez treści tokenów, haseł i szczegółów wydatków.

`apps/web/src/features/auth/`, `apps/web/src/app/api/auth/`, `apps/mobile/src/features/auth/`, `packages/database/prisma/schema.prisma`, ustawienia konta web/mobile. Skill lyamo-supabase; lyamo-github jeśli PR/CI.

## Kryteria odbioru

- Sesja web i ważny JWT wydane przed resetem są odrzucone po resecie; sprawdź rzeczywiste API.
- Ponowne użycie starego refresh tokenu jest wykrywane; równoczesne żądania sprawdzone na PostgreSQL.
- Nie można odwołać ani oglądać sesji innego użytkownika.
- Usunięcie konta i połączenie dostawcy wymagają świeżego potwierdzenia, także dla Google-only.
- Test mobile: login, refresh, logout, odzyskanie konta; opis kompatybilności i planu wdrożenia.
