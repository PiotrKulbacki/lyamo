# S10 — weryfikacja całości i wydanie

Cel: potwierdzić, że zmiany działają razem na docelowej infrastrukturze i można je kontrolowanie wdrożyć. Zależność: S09. Brak kolejnego zadania programu.

## Zakres

- Przeczytaj raporty etapów pod kątem kontraktów i nierozwiązanych braków. Uzupełnij testy przepływów, nie powtarzaj od zera całego audytu.
- E2E web/mobile: rejestracja hasłem/Google, link poprawny/wygasły, ponowienie maila, powrót po przerwaniu, odmowa zgody, FREE, MFA/passkey, sesja wygasła, reset odcinający inne urządzenie, checkout z kuponem, anulowanie i powrót do FREE.
- Zweryfikuj konfigurację Google, Brevo, Redis, Stripe i rozdzielenie środowisk Vercel/Supabase. W razie niepotwierdzonych integracji raportuj dokładnie brakujący test.
- Sprawdź aktualne advisories dla faktycznych wersji Next/React/auth i innych zależności dotykanych przepływem. Napraw istotne luki z kompatybilnymi aktualizacjami, bez niepowiązanego upgrade całego produktu.
- Wdroż właściwe nagłówki (CSP z bezpiecznym rolloutem/report-only gdzie potrzebne, frame-ancestors, HSTS po potwierdzeniu HTTPS, referrer, no-store dla odpowiedzi wrażliwych). Nie blokuj Google/Stripe i potrzebnych zasobów.
- Alarmy: wzrost błędów logowania, resetów, odmów limitu, awaria Redis/poczty, kolejka, nieudane webhooki i rozjazd uprawnień. Minimalizuj dane osobowe; ustal odbiorcę i retencję.
- Zadbaj o minimalne uprawnienia kont/kluczy i bazowego użytkownika DB, rozdzielenie roli migracji/runtime, ochronę preview i brak sekretów w bundlu/logach. Nie wyłączaj globalnie zabezpieczeń hostingu dla wygody testu.
- Przygotuj release z migracjami rozszerzającymi, backupem i sprawdzonym odzyskaniem, kolejnością kod/DB/mobile oraz rollbackiem, który nie reaktywuje dostępu. Brak zgody na destrukcyjne operacje nie blokuje przygotowania reviewable release.
- Jeśli zadanie obejmuje wdrożenie na nazwany cel i jest dostęp, wdrażaj oraz sprawdź rezultat. Jeśli nie, zakończ jako gotowe do wdrożenia z dokładnym pozostałym krokiem; nie nazywaj tego wdrożeniem.

## Skille i kryteria odbioru

Lyamo-github, lyamo-supabase, lyamo-vercel, lyamo-stripe wg operacji. Wszystkie checki CI oraz integracyjne/E2E przechodzą w znanym środowisku. Każdy nieprzetestowany element jest wymieniony; nie ukrywaj czerwonego checka. Sprawdź SHA działającej wersji, migracje i smoke test po wydaniu bez danych klientów.

Raport reports/S10.md zawiera stan wydania, wyniki, rollback, monitoring i pozostałe ryzyka. Zamknij STATUS.md dopiero zgodnie z faktycznie osiągniętym wynikiem; nowe problemy poza planem przedstaw użytkownikowi zamiast automatycznie uruchamiać nowy program.
