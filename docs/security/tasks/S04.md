# S04 — odzyskiwanie konta i bezpieczna poczta

Cel: zapewnić jednorazowe operacje i rzeczywiste dostarczanie potwierdzeń bez ujawniania tokenów. Zależność: S03. Następne: S05.

## Zakres

- Atomowo zużywaj token resetu/weryfikacji razem ze zmianą stanu. Warunkowa aktualizacja musi zapewniać dokładnie jednego zwycięzcę przy równoczesnych żądaniach.
- Zachowaj losowość, haszowanie w bazie, terminy ważności, unieważnianie nieaktualnych uprawnień oraz kontrakt odwołania sesji z S03.
- Wprowadź trwały outbox/kolejkę z retry i idempotencją, zgodną z Vercel. Zaprojektuj wysyłkę/retry tak, by token potrzebny do maila był krótko przechowywany bezpiecznie (np. szyfrowany payload), a po wysłaniu wygaszany/usuwany; nie przechowuj bezterminowo tokenu jawnie.
- Awaria poczty nie może usuwać jedynego działającego linku bez zapewnienia następnego; ponowna wysyłka ma cooldown. Nie ujawniaj istnienia konta szczegółem błędu dostawcy.
- Wyłącz analitykę na ekranach i callbackach z sekretami, usuń tokeny/e-maile z URL zdarzeń, logów i breadcrumbs Sentry/PostHog/Vercel Analytics. Dodaj właściwe no-store i politykę referrera.
- Usuń sekret z widocznego URL, gdy jest bezpiecznie przejęty przez ekran; unikaj przypadkowego zużycia linku przez skanery pocztowe. Sprawdź błędny/wygasły/zużyty link i przerwanie sieci.
- Wiadomości bezpieczeństwa z S03 korzystają z niezawodnego kanału; bez szczegółów finansowych. Ustal cleanup wygasłych tokenów, jobów i niepotwierdzonych rejestracji z bezpieczną retencją.

## Pliki i skille

`password-reset.service.ts`, `auth-email.service.ts`, `features/email/`, strony verify-email/reset-password, `features/analytics/`, konfiguracja Sentry, schemat Prisma. Skill lyamo-supabase; lyamo-vercel przy jobach. Brevo i telemetria: sekcja usług dodatkowych w INTEGRATIONS.md.

## Kryteria odbioru

- Test równoczesnego resetu na rzeczywistym PostgreSQL: jeden sukces; brak drugiej zmiany hasła.
- Symulacje awarii/timeout/retry dostawcy nie tworzą nieskończonej wysyłki i nie gubią możliwości odzyskania konta.
- Token nie trafia do żadnej włączonej telemetrii, również przy wcześniejszej zgodzie analitycznej.
- Sprawdzone wygasanie, ponowne wysłanie, skaner linków i treści wiadomości PL/EN/DE/ES.

Raport reports/S04.md opisuje joby, wymagane zmienne po nazwach, kontrakt cooldown i dostarczania dla S05.
