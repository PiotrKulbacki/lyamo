# S00 — powtarzalne środowisko i testy

Cel: przygotować jeden wiarygodny sposób weryfikowania kolejnych napraw. Zależność: brak. Następne zadanie: S01.

## Zakres

- Sprawdź `.nvmrc`, engines, lockfile, CI i dostępność runtime na hostingu. Ujednolić rozbieżny README; nie obniżaj ani nie podnoś wersji całego stacku bez potrzeby.
- Przygotuj zależności i wydzielony PostgreSQL do testów; nie odczytuj wartości produkcyjnych sekretów do raportu.
- Uruchom istniejące checki; udokumentuj błędy startowe i popraw tylko blokady potrzebne do testowania tego programu. Niezwiązane problemy zapisz oddzielnie.
- Zapewnij możliwość testów integracyjnych auth na odizolowanej bazie oraz testów przeglądarkowych. Wybierz lekki zestaw pasujący do repo; testy równoczesności muszą używać rzeczywistej bazy.
- Zapisz mapę potwierdzonych środowisk i połączeń w raporcie. Brak opcjonalnego dostępu do platform nie blokuje lokalnego S01.

## Kryteria odbioru

- Udokumentowane polecenia instalacji, format/lint/typecheck/test i build; znany wynik bazowy.
- Testy nie korzystają z danych klientów; build/migracje mają jawny cel testowy.
- Istnieje działający scenariusz integracyjny z utworzeniem i usunięciem danych testowych oraz instrukcja E2E.
- Raport odróżnia działające testy od niedostępnych zewnętrznych integracji.

Nie naprawiaj jeszcze mechanizmów logowania. Zaktualizuj STATUS.md i utwórz reports/S00.md, przekazując S01.
