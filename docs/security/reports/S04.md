## Zmiany i kontrakty

- Reset i potwierdzenie atomowo przejmują ważny, niezużyty token w transakcji pod blokadą użytkownika. Reset odwołuje sesje i inne linki; zmiana hasła unieważnia nieużyte resetowe. Stare konta, hasła i dane nie są zmieniane migracją. Testy PostgreSQL obejmują współbieżne użycie i nieaktualne linki.
- Powstanie hasha tokenu i zadania `mail_jobs` jest transakcyjne. Payload szyfruje AES-256-GCM z kluczem wyprowadzonym z `AUTH_SECRET`; do kolejki Vercel trafia tylko losowy identyfikator. Publishing przed zatwierdzeniem transakcji zapobiega utracie pobudzenia; przedwczesne dostarczenie jest ponawiane. Jeśli kolejka odmawia publikacji, transakcja jest wycofywana, więc operacja może zwrócić błąd; ponownie wyślij żądanie. Obrót `AUTH_SECRET` unieważnia oczekujące payloady.
- Vercel Queues (`security-mail`, prywatny consumer) budzi pracę, również na Hobby. Blokada z 30-sekundową dzierżawą, timeout Brevo 8 s, maksymalnie pięć prób z odstępami, stały UUID idempotencji Brevo i 25-minutowy termin (poniżej okna dostawcy 30 min). Przy niepowodzeniu lub timeout wcześniejszy link pozostaje ważny do własnego wygaśnięcia; po 60 s można poprosić o kolejny. Sukces czy wyczerpanie prób usuwa szyfrogram; dzienny job czyści wygasłe payloady, siedmiodniowe metadane oraz wygasłe tokeny. Istniejące rygorystyczne czyszczenie nowych niepotwierdzonych rejestracji zachowane.
- Zdarzenia S03 tworzą zadanie w tej samej transakcji; e-mail jest ogólny, bez danych finansowych. Istniejący model nie zapisuje preferencji językowej użytkownika, więc powiadomienia zdarzeń mają domyślny angielski; linki resetu i weryfikacji korzystają z locale żądania PL/EN/DE/ES. Retry jest ograniczone; brak obietnicy dostarczenia, gdy dostawca długotrwale niedostępny.
- Nowe linki przenoszą token we fragmencie, usuwanym z widocznego URL po przejęciu; stare linki z query pozostają obsługiwane. Potwierdzenie wymaga kliknięcia, nie samego GET; reset wymaga formularza. Adres rejestracji trafia do sessionStorage zamiast URL. No-store/no-referrer na ekranach i auth API; filtry Sentry, PostHog i Vercel Analytics odrzucają wrażliwe strony/URL/dane, nagrania sesji PostHog wyłączone. Część zdarzeń analitycznych z innymi query również jest odrzucana.

## Weryfikacja, wydanie i ograniczenia

- `npm run test:quality` na Node 26: sukces (format, lint, typy, 204 testy). Migrację zastosował izolowany runner jakości. Build, integracja PostgreSQL i E2E uruchamia CI PR; wynik bieżący w PR. Testy obejmują awarie, powtórzenia i limit prób; rzeczywiste doręczenie Brevo, ścieżka Queues/OIDC na Vercel oraz telemetria przy zapisanej zgodzie wymagają kontrolowanego, odizolowanego środowiska i skrzynki. Preview może współdzielić produkcyjną bazę i pomija migracje: nie używać go do testów auth.
- Migracja Prisma `20261105160000_mail_outbox` jest addytywna, z RLS i odebranymi uprawnieniami publicznym rolom. Nie wykonano zmian w zewnętrznej bazie; Production zastosuje migrację podczas deployu po merge użytkownika. Po migracji nowy kod wymaga działającego Vercel Queues/OIDC; potwierdzenie w tym projekcie nie zostało wykonane. [Dokumentacja Vercel](https://vercel.com/docs/queues/quickstart) opisuje automatyczne OIDC w deployment; [limity](https://vercel.com/docs/queues/pricing) obejmują Hobby. Aktywacja/beta i rzeczywista dostawa wymagają sprawdzenia przed merge. Nie publikować jako potwierdzonej usługi bez tego dowodu.
- Wysyłka testowa Brevo i ustawienia click trackingu nie zostały sprawdzone; śledzenie linków przez dostawcę może ujawnić link dostawcy. Przed odbiorem wyłączyć/zweryfikować śledzenie dla maili bezpieczeństwa i wykonać próbę na własnej skrzynce. Bez zmiany konfiguracji Vercel, Brevo, kont lub sekretów. Przy cofaniu zachować tabelę; stary kod nie realizuje nowych gwarancji sesji/odzyskiwania. Bez zmian kontraktu mobile API; istniejące linki pozostają obsługiwane.
- Jeśli Vercel Queues nie jest dostępne, trzeba zapewnić inny zweryfikowany sposób niezawodnego pobudzania outboxu przed merge; pięciominutowy Vercel Cron nie działa na obecnym Hobby. Użytkownik zaoferował cron-job.org, ale sama zmiana harmonogramu nie usuwa wymogu atomowego zapewnienia pobudzenia po zapisie.
