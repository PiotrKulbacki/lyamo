## Zmiany i kontrakty

1. `.cursorrules` odwołuje się do rzeczywistej konfiguracji zamiast narzucać Tailwind v4/alternatywny ORM i przyszłe funkcje. Formatowanie tylko zmienionych plików, ochrona cudzej pracy, Prisma jako właściciel migracji i izolacja S00.
2. `safeAuthRedirect` dopuszcza istniejące ścieżki panelu z query/hash. Schematy wykonywalne, obce adresy, backslash, znaki kontrolne i zakodowane ścieżki dają `/dashboard`. Nowe trasy wymagają dopisania do listy. AuthForm sprawdza wartość przed nawigacją.
3. Middleware nie uznaje cookie za ważną sesję ani nie przekierowuje publicznych stron na tej podstawie. Layout autoryzuje przez bazę. `/api/auth/session/clear` ponownie sprawdza sesję i usuwa cookie tylko przy nieważnej sesji (GET nie odwołuje ważnej, `no-store`). `/api/auth/me` czyści cookie przy 401.
4. Wszystkie 32 mutujące handlery poza podpisanym webhookiem Stripe wywołują `protectMutation` przed skutkami ubocznymi. Callback Google zachowuje GET/state. Nie zmieniono łączenia kont, cyklu tokenów ani schematu.
5. Wspólne ustawianie/czyszczenie `sec_session`: HttpOnly, SameSite=Lax, Path=/, Secure w produkcji, bez Domain. Zachowano aktywne sesje. Rozważony `__Host-` wymaga osobnego rollout: nowa nazwa zapisu, wygaszanie starej przy zapisie/wylogowaniu, zakończenie starego odczytu po maksymalnym czasie sesji; bez takiej migracji w S01.
6. Testy jednostkowe i E2E obejmują przekierowania, logowanie, sesje nieznane/wygasłe/usunięte, CSRF i native mobile. Syntetyczne fixtures są usuwane.

`protectMutation(request, { bearer?, multipart?, bodyless? })` zwraca null albo 403/415 z istniejącym tłumaczeniem `auth.errors.generic`. Web wymaga dokładnego Origin z `NEXT_PUBLIC_APP_URL` (nie Host), odpowiedniego Fetch Metadata i JSON. Multipart włączono wyłącznie dla skanera. `bodyless: true` pozwala pominąć Content-Type tylko w handlerach obsługujących żądania bez treści (logout, portal, odpowiednie DELETE); kontrola Origin pozostaje obowiązkowa. Vercel może udostępniać pusty request jako strumień bez Content-Length.

Cookie-free native JSON bez Origin/Fetch Metadata działa również dla login/refresh. Inny Origin można pominąć tylko w handlerze faktycznie używającym zweryfikowanego Bearera (`bearer: true`), bez cookies. Sam Authorization lub `x-client-platform` nie zwalnia cookies z CSRF. Nie otwieraj dowolnego CORS. Aliasy i preview nie są automatycznie zaufane; publiczny URL musi odpowiadać domenie aplikacji.

Źródła wzorca: [OWASP CSRF](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html), [Next.js cookies](https://nextjs.org/docs/app/api-reference/functions/cookies).
